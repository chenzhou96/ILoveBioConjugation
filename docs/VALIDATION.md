## 已修复的关键问题

1. **单底物矛盾条件被当作成功**：同时填写的取用量、终浓度和总体积现在必须满足稀释守恒
2. **多底物信息不足仍返回空结果**：只有全部必要结果和约束一致后才提交结果
3. **自动改变目标体积**：母液过量时明确拒绝，不再悄悄放大体系或改变终浓度
4. **非法数值与单位**：拒绝 NaN、Infinity、越界/下溢、未知单位、非法零值和负值
5. **浓度基准不一致**：质量/摩尔浓度保持同步；缺少分子量时不会忽略不兼容的终浓度输入
6. **微小数值被容差吞掉**：约束比较使用相对容差，覆盖 pM/pL 及更小数量级边界
7. **历史恢复失真**：原始字符串、单位、空白未知量与启用槽位单独保存；不再把 nM/pM 恢复为零，不继承旧计算多余槽位
8. **数据层完整性**：SQLite v1→v2 升级、结果与输入快照事务保存、失败回滚、页内两次查询替代 N+1 查询
9. **异步/导航生命周期**：旧保存失败不覆盖新计算；导航离开时完成删除仍会刷新历史缓存
10. **模板残留参数**：加载会清除模板未提供的字段和旧取样体积；无效数字不能悄悄变成空值后保存
11. **损坏的历史单位标签**：结构合法但单位非法的快照会回退到旧结果恢复，避免下拉框崩溃
12. **潜在单位常量错误**：通用质量单位表的 ng/pg 指数已纠正。该表未用于现有 Flutter 界面的 ng/mL、pg/mL 浓度换算，因此不能据此断言旧界面结果曾出现 1000 倍错误

## 编译与平台限制

已成功编译应用真实主入口的 Dart kernel：

```sh
flutter assemble --output=build/qa-kernel \
  -dTargetPlatform=linux-x64 -dBuildMode=debug \
  -dTargetFile=lib/main.dart kernel_snapshot_program
```

**这不是可分发安装包验证。** 默认 `flutter build bundle` 受缺少 Android SDK 阻塞；指定 Linux bundle 又需要原生 CMake 构建配置，当前仓库没有 Linux 平台工程。Windows/macOS/iOS 原生构建和安装器需要对应平台，未在这台 Linux 云端运行。

发布前应在 Windows 上执行 `flutter build windows --release`，确认 `sqlite3.dll` 与 EXE 一同分发，并验证：首次启动、真实历史备份后的升级、设置重启恢复、模板、复制结果和本机菜单行为。当前交付没有包含新编译的 EXE；仓库原有安装器仍是旧版本。

## 使用边界

- 保留既有推导规则：未填总体积且全部母液体积已知、没有终浓度决定总体积时，采用母液体积之和，即不额外补溶剂
- 展示值经过适度格式化，内部计算和新历史的原始输入不使用展示舍入值
- 计算器不判断反应化学可行性、试剂兼容性或移液器量程；执行实验前仍需核对
